Events

Cyrus relies heavily on events, therefore we wanted to great the gold standard on event handling. The gold standard is the Sponge api, thanks to its event system being linked with its cause system, allowing filtering of the event handler to more exact changes.

Cyrus also has an event system so the events can be filtered in the same way as Sponge. But let's not get ahead of ourselves and instead focus on the basics.

Event handling - basics

Basic event handler example

@EventHandler
public static void onBlockChange(BlockChangeEvent event){
    //logic
}

The following example will trigger when a block change occurs, if this is placed in your main class then there is no need to register it.

The key ingredients to make the event handler trigger are as follows:

Annotation

@EventHandler

This annotation marks the method it is connected to as the event handler for the provided event.

Class

BlockChangeEvent

This is the event type that the event handler. There are many events within Cyrus, a full list can be found here. In the example we are listening for the BlockChangeEvent which as the name implies, triggers when a block is changed.

Event handling - filtering

Getter

Getter annotation

@EventHandler
public static void onBlockChange(BlockChangeEvent event, @Getter("transaction") BlockTransaction.Break transaction){
    //logic
}

The following example has a second parameter of @Getter("transaction") BlockTransaction.Break. With this the event handler will only trigger if the event function of event.transaction() returns a object that is assignable to BlockTransaction.Break. Traditionally this method returns a object that is always assignable to BlockTransaction.
